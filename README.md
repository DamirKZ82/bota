# Бота — ИИ-агент бухгалтера для «1С:Бухгалтерия для Казахстана»

Сценарий 1 (MVP): сверка поступлений и полученных ЭСФ с поиском расхождений.
Техническое задание — [docs/ТЗ_Агент_Сверка_ЭСФ_v0.2.md](docs/%D0%A2%D0%97_%D0%90%D0%B3%D0%B5%D0%BD%D1%82_%D0%A1%D0%B2%D0%B5%D1%80%D0%BA%D0%B0_%D0%AD%D0%A1%D0%A4_v0.2.md).

Этот репозиторий — **оркестратор**: внешний сервис между базой 1С и языковой моделью.
Расширение 1С (движок сверки, HTTP-сервис, форма диалога) разрабатывается отдельно.

## Запуск

```bash
python -m venv .venv && .venv/Scripts/python -m pip install -e ".[dev]"
```

```bash
.venv/Scripts/python -m pytest
```

```bash
.venv/Scripts/uvicorn orchestrator.main:app --reload
```

Без переменной `BOTA_TRANSPORT` оркестратор работает на мок-данных — база 1С не нужна.
Для реальных вызовов модели нужен `ANTHROPIC_API_KEY` в `.env` (см. `.env.example`).

Проверить реестр инструментов: `GET /v1/tools` — эта же выдача служит спецификацией
для разработчика расширения 1С.

Задать вопрос агенту:

```bash
curl -s -X POST http://localhost:8000/v1/chat/ask -H "Authorization: Bearer demo-token" -H "Content-Type: application/json" -d "{\"message\":\"Сверь поступления и ЭСФ за 2 квартал\"}"
```

## Устройство

```
orchestrator/
  agent/       цикл tool calling, системный промпт
  llm/         абстракция провайдера модели + адаптер Claude API
  tools/       контракты (Приложение А), реестр, исполнитель
  transport/   каналы до 1С: direct, polling, mock
  masking/     псевдонимизация данных перед отправкой в модель
  api/         маршруты FastAPI
```

Четыре принципа, на которых держится код (ТЗ п.3.1):

1. **Модель не считает — модель объясняет.** Суммы, допуски и сопоставление — код в 1С.
   Оркестратор передаёт готовый результат и не пересчитывает его.
2. **Модель не имеет доступа к базе.** Только вызов инструментов из реестра с
   параметрами, проверенными контрактом. Произвольные запросы невозможны.
3. **Запись только с подтверждением.** Инструменты `plan_*` возвращают план изменений;
   применяет его пользователь кнопкой в 1С. Фазы 2 в реестре инструментов нет —
   агент физически не может её вызвать.
4. **Минимум данных наружу.** Маскирование применяется при приёме результата от 1С,
   а не перед вызовом модели, — тогда реальные наименования не попадают и в журнал.
