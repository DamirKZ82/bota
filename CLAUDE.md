# Правила разработки — bota

Адаптация backend-guidelines из stroy-smeta под этот проект. Расхождения с
исходными правилами отмечены и обоснованы — они вызваны предметной областью:
здесь бухгалтерские данные нескольких клиентов в одной базе и продукт, весь смысл
которого в копейках и датах.

---

## 1. Стек

Python 3.12+, FastAPI, PostgreSQL, asyncpg, httpx (async), Pydantic v2.
Прод: NGINX + systemd. Тесты: pytest.

---

## 2. Деньги — только Decimal, никогда float

Предмет продукта — расхождения в 0,01 ₸. `float` сам является источником такой
ошибки, поэтому в контрактах, расчётах и БД денег с плавающей точкой нет.

**Плохо:**
```python
amount_vat: float
total = sum(line.amount_net * 0.12 for line in lines)
```

**Хорошо:**
```python
from decimal import Decimal
amount_vat: Decimal        # в БД NUMERIC(15, 2)
```

И главное: **оркестратор не считает суммы вообще**. Арифметику делает движок
сверки в 1С, здесь только передача и отображение. Появился в коде оркестратора
расчёт суммы — значит, что-то спроектировано неверно.

---

## 3. Даты — нативные типы, не CHAR

> Расхождение с исходным гайдлайном (п.2, `CHAR(19)`/`CHAR(10)`). Причина: весь
> домен — арифметика дат. «Хвост периода +20 дней», «срок выписки ЭСФ истёк»,
> «дата оборота в другом квартале НДС» (код D08), «плательщик НДС на дату».
> На CHAR это превращается в парсинг в Python вместо вычисления в БД.

В БД: `DATE` для дат, `TIMESTAMPTZ` для моментов времени.
В коде: `datetime.date` / `datetime.datetime`.

**Плохо:**
```python
if receipt["date"][:7] != esf["turnover_date"][:7]:  # сравнение кварталов срезом строки
```

**Хорошо:**
```sql
WHERE turnover_date BETWEEN $1 AND $1 + INTERVAL '20 days'
```

Форматирование для показа пользователю — в одном месте, `libs/format.py`,
локальные хелперы не плодить. Суммы пользователю: `1 234,56 ₸`.

---

## 4. SQL — только параметризованный

> Расхождение с исходным гайдлайном (п.3, f-strings + `fit_to_sql`). Причина:
> оркестратор multi-tenant, в одной базе данные нескольких клиентов-аутсорсеров,
> разделённые только `tenant_id`. Одно забытое экранирование — и запрос одного
> клиента читает данные другого. asyncpg поддерживает `$1` нативно.

**Плохо:**
```python
await query_db(f"SELECT * FROM dialogs WHERE tenant_id = '{tenant_id}'")
```

**Хорошо:**
```python
await query_db("SELECT * FROM dialogs WHERE tenant_id = $1", tenant_id)
```

`tenant_id` в условии **обязателен** в каждом запросе к таблицам с данными баз.
Запрос без него — ошибка, даже если кажется, что выборка и так однозначна.

---

## 5. Ошибки — два типа

Как в исходном гайдлайне, берём без изменений.

**Пользовательские** — некорректный запрос, инженер не нужен:
```python
raise WarnException(404, "Расхождение не найдено")
raise WarnException(403, "Нет права «Агент: создание документов»")
```

**Системные** — сбой, требует разбора:
```python
raise ErrorException(err=err, sql=sql)
```

Правила:
- Строго 2xx только при успехе. Никаких `{"success": false}` со статусом 200.
- Сообщение пользователю — понятное, без трейсбеков и `NoneType has no attribute`.
- Глобальный хендлер сам пишет в журнал и уведомляет; в роутерах ничего не оборачивать.

Отдельный случай — **ошибка инструмента**. Она не поднимается наверх, а возвращается
модели как `tool_result` с `is_error: true`, чтобы та исправила параметры или
сообщила пользователю. См. `tools/executor.py`.

---

## 6. Логи — structlog, и никогда данные документов

> Расхождение с исходным гайдлайном (п.14, `print`). Причина: в логи не должны
> попадать наименования контрагентов, БИН и номенклатура. `print` этого не
> контролирует и не даёт уровней.

Маскирование выполняет расширение 1С (Приложение А, A.0.5): таблица псевдонимов
живёт там, оркестратор соответствий не знает. Значит, в логи и так попадают
только псевдонимы — но это следствие настройки базы, а не гарантия. Значения
параметров запросов не логируем никогда.

**Плохо:**
```python
print(f"[{ts}] Сверка по {counterparty_name}")
log.info("tool_call", payload=response.result)   # весь ответ 1С целиком
```

**Хорошо:**
```python
log.info("tool_call", tool="get_discrepancy", tenant_id=tenant_id, ok=True)
```

В журнал (`db/repo/journal.py`) идут метаданные вызова: инструмент, аргументы
(они приходят от модели, то есть уже в псевдонимах), код ошибки, длительность.

---

## 7. Валидация — контрактами, а не проверками в роутере

Все контракты наследуют `Contract` (`extra="forbid"`, `frozen=True`). Лишнее поле
от 1С — ошибка контракта, а не молча проглоченное значение: иначе агент увидит
неполные данные и назовёт неверную цифру.

Базовая валидация — в моделях, бизнес-случаи — в роутере через `WarnException`.

Типовые валидации домена: БИН/ИИН ровно 12 знаков, код валюты 3, ставка НДС 0–100,
количество > 0, цена ≥ 0, коды расхождений — только из `tools/enums.py`.

---

## 8. Классы — только точки замены

> Уточнение к исходному п.13 («модули вместо классов»). Классов в проекте ровно
> три, и все — абстракции с несколькими реализациями:

- `LLMProvider` — внешняя модель против локальной (вопрос 5 раздела 10 ТЗ открыт);
- `OneCTransport` — прямой режим, поллинг, мок;
- `DialogStore` — история в памяти против Postgres.

Всё остальное — функции и Pydantic-модели. Новый класс без второй реализации
или без состояния — повод переписать функцией.

## 9. Структура

```
orchestrator/
  agent/       цикл tool calling, системный промпт
  llm/         абстракция провайдера + адаптеры
  tools/       контракты, реестр, исполнитель, справочники кодов
  transport/   direct, pg_polling, mock
  api/         маршруты FastAPI
  db/          схема, миграции, репозитории
  libs/        общие хелперы (формат, даты)
tests/
docs/
```

Роутеры без нумерации префиксами — их три, а не тридцать. Регистрируются явно
в `main.py`: неявная автозагрузка на таком размере только прячет порядок.

Префикс версии — в роутере (`/v1/chat`), не в каждом маршруте.

---

## 10. Конфиг и env

- `.env` — только секреты: `ANTHROPIC_API_KEY`, пароль БД, токены баз.
- `config.py` — всё несекретное: модель, лимиты, таймауты, порты.
- Отсутствие обязательного параметра — падение при старте с понятным сообщением,
  а не `None` в середине запроса.

Хардкод в коде запрещён: `max_tool_calls`, интервалы поллинга, допуски по
умолчанию — всё в конфиге или в настройках базы.

---

## 11. Импорты, именование, HTTP

- Импорты абсолютные: `from orchestrator.tools.registry import BY_NAME`.
- Исключение называется `err`, не `e`. Встроенные имена не затенять (`items_map`, не `map`).
- HTTP только `httpx` async, с явным таймаутом. `requests` не использовать.
- `main.py` — только lifespan, приложение и подключение роутеров.

---

## 12. Тесты — обязательны

> Раздела нет в исходном гайдлайне. Причина: критерий пилота — «≥95 % найденных
> расхождений, ≤10 % ложных срабатываний». Без набора эталонных кейсов это
> невозможно ни подтвердить, ни удержать при доработках.

Обязательно покрываются:

1. **Контракты против мока** — каждый инструмент проходит валидацию входа и выхода.
   Когда появится расширение 1С, этот же набор становится приёмочным тестом
   HTTP-сервиса.
2. **Кейсы расхождений** — каждый код R1–R6 и ключевые D-коды имеют тест с
   конкретными суммами. Новый паттерн расхождения приходит в проект вместе с тестом.
3. **Правила безопасности** — отсутствие `apply_*` в реестре, лимит вызовов,
   изоляция баз по `tenant_id`.

Тесты называются по-русски, утверждением: `test_лимит_вызовов_даёт_промежуточный_ответ`.
Название теста — это описание требования, а не имя функции.

Модель в тестах не вызывается: провайдер подставной (`ScriptedProvider`).

## 13. Правила, специфичные для агента

Нарушение любого из них — не стилистическая придирка, а нарушение ТЗ:

1. **Оркестратор не считает суммы.** См. п.2.
2. **Модель не имеет доступа к базе.** Только инструменты из реестра
   (`tools/registry.py`) с параметрами, проверенными контрактом.
3. **Фазы 2 в реестре инструментов нет.** Применение изменений вызывает
   пользователь из 1С. Инструмент с именем на `apply_`/`применить` в реестре —
   ошибка, на это есть тест.
4. **Маскирование делает 1С, а не оркестратор** (A.0.5). Оркестратор передаёт
   флаг `masking` и `session_id` в контексте вызова и никогда не хранит
   соответствия «псевдоним → реальное значение».
5. **Порядок инструментов в `TOOLS` — часть кэш-префикса запроса.** Менять порядок
   и текст системного промпта без причины нельзя: это инвалидирует кэш всех баз.
6. **Новый инструмент = контракт + запись в реестре + мок + тест.** Все четыре,
   одним коммитом; тест `test_у_каждого_инструмента_реестра_есть_проверка` это стережёт.
7. **Источник истины по контрактам — Приложение А** (`docs/`). Расхождение кода с
   ним — ошибка кода, а не документа. Имена полей из Приложения (`from`, `to`)
   сохраняются в JSON через alias, даже когда внутри Python зовутся иначе.
