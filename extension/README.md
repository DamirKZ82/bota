# Расширение «Агент» — сборка в конфигураторе

Здесь лежит код модулей. Объекты метаданных создаются в конфигураторе по этому
описанию: так весь объём работы уходит в алгоритмы, а не в перенос XML.

Полная спецификация — [../docs/Спецификация_расширения_1С_v0.1.md](../docs/%D0%A1%D0%BF%D0%B5%D1%86%D0%B8%D1%84%D0%B8%D0%BA%D0%B0%D1%86%D0%B8%D1%8F_%D1%80%D0%B0%D1%81%D1%88%D0%B8%D1%80%D0%B5%D0%BD%D0%B8%D1%8F_1%D0%A1_v0.1.md),
контракты инструментов — [../docs/Bota_Приложение_А_Контракты_инструментов_v0.1.md](../docs/Bota_%D0%9F%D1%80%D0%B8%D0%BB%D0%BE%D0%B6%D0%B5%D0%BD%D0%B8%D0%B5_%D0%90_%D0%9A%D0%BE%D0%BD%D1%82%D1%80%D0%B0%D0%BA%D1%82%D1%8B_%D0%B8%D0%BD%D1%81%D1%82%D1%80%D1%83%D0%BC%D0%B5%D0%BD%D1%82%D0%BE%D0%B2_v0.1.md).

> **Код не проверялся в 1С.** Он написан по спецификации и вычитан статическим
> анализатором (`python scripts/lint_bsl.py`), но ни разу не компилировался:
> платформы на машине разработчика оркестратора нет. Первый прогон в
> конфигураторе наверняка потребует правок — прежде всего в именах реквизитов
> типовой.

## Порядок сборки

1. **Создать расширение**: имя `Бота`, префикс `Бота`, назначение
   «Дополнение», режим совместимости — как у основной конфигурации.
2. **Добавить общие модули** из `modules/` (см. таблицу ниже) — на этом этапе
   уже можно выполнить самопроверку.
3. **Выполнить самопроверку имён** в консоли:

   ```bsl
   Проблемы = БотаМетаданныеТиповой.ПроверитьСовместимость();
   Для Каждого Проблема Из Проблемы Цикл
       Сообщить(Проблема);
   КонецЦикла;
   ```

   Пустой результат означает, что расширение видит все нужные объекты типовой.
   Каждая строка — имя, которое нужно поправить в `БотаМетаданныеТиповой.Имена()`.
   **Это единственное место, где имена типовой прописаны.**

4. **Создать регистры сведений** (таблица ниже) — они нужны кэшу расчёта,
   пометкам и журналу.
5. **Опубликовать HTTP-сервис** и проверить его приёмочным скриптом
   оркестратора.

## Общие модули

Все — серверные, без вызова сервера с клиента.

| Модуль | Готов | Назначение |
|---|---|---|
| `БотаМетаданныеТиповой` | да | Имена объектов типовой, самопроверка, чтение строк документов |
| `БотаДвижокСверки` | да | Формирование пар «поступление ↔ ЭСФ», поиск кандидатов |
| `БотаСопоставлениеСтрок` | да | Пять уровней построчного сопоставления, нормализация, похожесть |
| `БотаПаттерныОкругления` | да | Определение R1–R6 и тексты объяснений |
| `БотаКлассификатор` | да | Коды D01–D16, критичность, идентификаторы расхождений |
| `БотаСверкаПериода` | да | Полный расчёт периода, кэш, сводка Приложения А |
| `БотаНастройки` | да | Допуски, хвост периода, режим маскирования |
| `БотаИнструменты` | нет | Экспортные функции инструментов Приложения А |
| `БотаМаскирование` | нет | Псевдонимы и обратная подстановка |
| `БотаЖурнал` | нет | Запись вызовов и применённых изменений |
| `БотаОбменСОркестратором` | нет | Подпись запросов, поллинг, разбор конверта |
| `БотаПодборНоменклатуры` | нет | Подбор номенклатуры и счетов при создании по ЭСФ |

## Регистры сведений

Все — независимые, если не указано иное. Префикс имён — `Бота`.

### БотаКэшРасчёта

Кэш сверки периода, TTL 24 часа. Инвалидируется при записи любого поступления
или ЭСФ соответствующего периода.

| | Имя | Тип |
|---|---|---|
| Измерение | ИдРасчёта | Строка (36) |
| Измерение | Организация | СправочникСсылка.Организации |
| Измерение | ДатаНачала | Дата (дата) |
| Измерение | ДатаОкончания | Дата (дата) |
| Ресурс | ДанныеРасчёта | ХранилищеЗначения |
| Ресурс | ДатаРасчёта | Дата (дата и время) |

### БотаРасхождения

Разложенные карточки: чтобы `get_discrepancy` не пересчитывал период заново.

| | Имя | Тип |
|---|---|---|
| Измерение | ИдРасчёта | Строка (36) |
| Измерение | ИдРасхождения | Строка (16) |
| Реквизит | Код | Строка (3) |
| Реквизит | Критичность | Строка (10) |
| Реквизит | Паттерн | Строка (2) |
| Реквизит | Поступление | ДокументСсылка (составной) |
| Реквизит | ЭСФ | ДокументСсылка (составной) |
| Реквизит | Контрагент | СправочникСсылка.Контрагенты |
| Реквизит | ВлияниеНДС | Число (15, 2) |
| Ресурс | ДанныеКарточки | ХранилищеЗначения |

Индекс по `Код` и `Критичность` обязателен: `list_discrepancies` фильтрует
именно по ним, и без индекса выборка на 5 000 расхождений будет медленной.

### БотаПометки

Пометка «рассмотрено» живёт отдельно от расчёта — иначе она слетала бы при
каждом пересчёте периода.

| | Имя | Тип |
|---|---|---|
| Измерение | ИдРасхождения | Строка (16) |
| Реквизит | Статус | Строка (10) |
| Реквизит | Комментарий | Строка (500) |
| Реквизит | Пользователь | СправочникСсылка.Пользователи |
| Реквизит | Дата | Дата (дата и время) |

### БотаСоответствияНоменклатуры

Обучение на базе клиента: каждое подтверждённое сопоставление запоминается.

| | Имя | Тип |
|---|---|---|
| Измерение | Контрагент | СправочникСсылка.Контрагенты |
| Измерение | НаименованиеНормализованное | Строка (200) |
| Реквизит | Номенклатура | СправочникСсылка.Номенклатура |
| Реквизит | Подтверждено | Булево |
| Реквизит | Дата | Дата (дата и время) |

Наименование хранится **нормализованным** (`БотаСопоставлениеСтрок.Нормализовать`):
поиск идёт по нему, а не по исходному написанию поставщика.

### БотаПсевдонимы

Таблица маскирования (Приложение А, A.0.5). Ключ — сессия диалога.

| | Имя | Тип |
|---|---|---|
| Измерение | СессияId | Строка (36) |
| Измерение | Псевдоним | Строка (50) |
| Реквизит | Вид | Строка (20) |
| Реквизит | Значение | Строка (500) |

Именно здесь проходит граница ответственности: оркестратор псевдонимов не
знает вовсе, обратную подстановку делает форма.

### БотаПланы

План изменений между фазой 1 и фазой 2. Срок жизни — 30 минут (A.9).

| | Имя | Тип |
|---|---|---|
| Измерение | ПланId | Строка (36) |
| Реквизит | Действие | Строка (50) |
| Реквизит | СрокДействия | Дата (дата и время) |
| Реквизит | Применён | Булево |
| Реквизит | Пользователь | СправочникСсылка.Пользователи |
| Ресурс | ДанныеПлана | ХранилищеЗначения |

### БотаЖурналДействий

Журнал агента (ТЗ п. 8). Периодический, в пределах секунды.

| | Имя | Тип |
|---|---|---|
| Измерение | ПланId | Строка (36) |
| Реквизит | Действие | Строка (50) |
| Реквизит | СессияId | Строка (36) |
| Реквизит | Пользователь | СправочникСсылка.Пользователи |
| Реквизит | Документы | Строка (неограниченная) |
| Реквизит | СсылкаОтката | ДокументСсылка (составной) |

## Прочие объекты

| Объект | Имя | Примечание |
|---|---|---|
| HTTP-сервис | `Бота` | Корневой URL `bota`, шаблон `/v1/tools/{tool}`, метод POST |
| Константы | `БотаТокенБазы`, `БотаКлючПодписи`, `БотаАдресОркестратора`, `БотаМаскирование` | Настройки обмена |
| Константа | `БотаИдентификаторБазы` | Строка (36). Генерируется сама при первом расчёте. Нужна для устойчивых идентификаторов расхождений: при переносе базы они не должны меняться, иначе слетят все пометки «рассмотрено» |
| Константы | `БотаДопускНаЕдиницу`, `БотаПотолокСтроки`, `БотаДопускНаСтроку`, `БотаПотолокДокумента`, `БотаПорогПериода`, `БотаХвостПериодаДней`, `БотаДнейДопускКандидата` | Число (15,2) и целые. Пустая константа означает «значение по умолчанию из ТЗ» |
| Регламентное задание | `БотаОбменСОркестратором` | Поллинг, интервал 5–15 с |
| Роль | `БотаЧтение` | Доступ к инструментам чтения |
| Роль | `БотаПрименениеИзменений` | Фаза 2: применение планов |
| Роль | `БотаСозданиеДокументов` | Создание поступлений по ЭСФ |
| Обработка | `БотаСверка` | Отчёт на СКД поверх движка (этап 1) |
| Обработка | `БотаАгент` | Форма диалога с индикацией шагов |
| Реквизит документов | `БотаСозданАгентом` | Булево + `БотаСессияДиалога` (Строка 36) |

Реквизит `БотаСозданАгентом` добавляется в расширении к документу поступления:
без него созданную агентом пачку невозможно найти и откатить (ТЗ п. 5.2).

## Проверка

Статический анализ модулей — из корня репозитория:

```bash
python scripts/lint_bsl.py
```

Ловит то, что ловится без компилятора: смешанные алфавиты в идентификаторах
(латинская «e» в русском слове невидима глазами) и разбалансированные блоки.

Приёмочная проверка HTTP-сервиса против контрактов Приложения А:

```bash
python scripts/verify_extension.py --base-url http://localhost/WK --token ТОКЕН --key КЛЮЧ
```
